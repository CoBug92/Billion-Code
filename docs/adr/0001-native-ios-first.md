# ADR-0001: начать с native iOS

- Статус: `accepted`
- Дата: 2026-08-31
- Decision register: P-004, P-005

## Контекст

Исходное продуктовое исследование рекомендовало сначала mobile web: это дешевле для проверки спроса и шаринга. Пользователь отдельно уточнил, что хочет начать именно с native iOS. Решение меняет способ проверки, но не отменяет риски исследования: ценность графа и регулярное возвращение ещё не доказаны.

## Рассмотренные варианты

1. Mobile web/PWA как самый дешёвый demand test.
2. Native SwiftUI-приложение для iPhone.
3. Кроссплатформенный клиент.

## Решение

Первая продуктовая реализация — native SwiftUI для iPhone, portrait-only, iOS 18+. Xcode project, target и module называются `BillionCode`; русское storefront name — «Код миллиарда».

Текущий документационный этап не создаёт проект. Принятие платформы не означает принятие всей предложенной архитектуры.

## Последствия

Положительные:

- доступ к нативной accessibility-модели, gestures, focus и системной навигации;
- честная проверка выбранного пользователем продукта;
- единый Apple toolchain для MVP.

Отрицательные:

- выше стоимость и время первой проверки, чем у mobile web;
- ссылка не открывает продукт мгновенно вне TestFlight/App Store;
- нет Android/web-аудитории и сложнее вирусное распространение;
- ценность native формата пока является допущением, а не результатом эксперимента.

## Риски и меры

- Риск преждевременной инженерной инвестиции ограничивается 15 профилями и закрытым TestFlight.
- Graph и content storage проходят отдельные spikes до production реализации.
- Web, iPad, Android и landscape явно остаются non-goals MVP.
